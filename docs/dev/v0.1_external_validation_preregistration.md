# v0.1 external differential validation — preregistration

**Status:** revised per the external-validation decision report (26 Nov 2026),
draft for final sign-off. The review's design decisions are applied (comparator
versions pinned; C1 synthetic-truth-primary with a bounded pilot margin; C3 locked
to numerical equivalence; C4 Dice-primary, gated+diagnostic; C5 metric family
corrected; A21-016 excluded from confirmatory C4/C5 because suitable independent
reference evidence is not documented in the validation record — not because it lacks
an XRF map or AXIOMM result, both of which exist; the post-hoc known-difference
waiver removed). The per-comparison criteria are in `v0.1_acceptance_criteria.md`.
Nothing is run until every applicable criterion, comparator version, dataset split
and threshold-selection rule is signed off and committed; expected metrics and the
sealed protocol are recorded in advance so a favourable result cannot be
manufactured after the fact.

**Why this exists.** Internal self-review has reached diminishing returns: recent
audits found defects in AXIOMM's own fixes, and passing more internally-generated
tests does not establish correctness relative to established analysis systems.
This plan replaces open-ended internal auditing with a bounded external comparison.
It complements, and does not replace, `quantification_validation_freeze.md` (the
quant-path freeze) and `real_dataset_readiness.md` (the real-data conversion
checklist).

## 0. Freeze of the v0.1 scientific contract

The v0.1 scientific pipeline is **frozen** for release-candidate purposes: maps →
decomposition → clustering → cluster means → quantification (uncorrected
Cliff–Lorimer) → reliability gate → mineral matching → classification → report,
including the multi-energy fusion path (joint acquisition eligibility, per-element
source selection with fallback, bridge cross-calibration, provenance) and
save/load. Behaviour is pinned by the existing test suite.

After the freeze:

- Only **P0/P1** defects may reopen the release candidate.
  - **P0** — data loss or corruption, a security failure, or failure of the
    primary public workflow from a clean environment.
  - **P1** — a reproducible error that can silently change a scientific
    conclusion, fabricate evidence, classify unavailable evidence as observed, or
    prevent reproduction of a result.
- **P2/P3** — API refinement, additional status granularity, broader exporters,
  performance work, speculative scientific enhancements — go to the versioned
  post-release backlog (§8). They **must not** trigger another general audit.

## 1. The release claim (narrow, falsifiable)

> AXIOMM provides a reproducible, provenance-rich pipeline from spectral maps to
> reliability-gated and abstention-capable mineral interpretation, while exposing
> rather than concealing unavailable or insufficient evidence.

**Not claimed** (and therefore not what validation must prove): outperforming
mature XRF spectrum-fitting packages; producing a validated, matrix-corrected
*quantitative* composition; or performing *independent* mineral identification.
Agreement with another software package is not ground truth; only standards and
expert mineralogy are.

## 2. Known model differences — declare before comparing

A difference listed here is **expected** and is not, by itself, a failure.

- **Uncorrected quantification.** AXIOMM's wt% are theoretical
  sensitivity-ratio (Cliff–Lorimer) estimates with **no** matrix correction,
  detector-efficiency/geometry term, self-absorption, or secondary fluorescence.
  They will differ **systematically** from matrix-corrected quant (PyMca/PyXRF).
  Compare **relative** composition (cation ratios), not absolute wt%, and expect a
  documented systematic offset.
- **Match metric.** AXIOMM ranks by cosine similarity on cation proportions
  (higher = better). Other tools use different conventions (e.g. L¹ on atomic
  fractions, lower = better). **Do not merge scores** across tools.
- **Reference circularity.** `minerals_default_v2` endmembers come from the same
  experimental suite as the test data; this supports internal consistency, not
  independent identification.
- **Abstention by design.** AXIOMM returns `unresolved` / no-measurement states on
  purpose. A tool that always names a phase is not a stricter baseline; it is a
  different policy.

## 3. Baselines — what each one validates

Each tool has a **defined role**; they are not interchangeable. Begin with PyMca
and HyperSpy; add PyXRF only if it provides a materially distinct comparison
without delaying the release candidate. Installation/format-integration work is
bounded — do not integrate every possible package.

| Baseline | Role | Does **not** establish |
|---|---|---|
| **PyMca** | **Primary** XRF spectrum-fitting and quantitative-analysis comparator (net line intensities, quant behaviour) | AXIOMM's uncorrected wt% are "right" in absolute terms |
| **HyperSpy** | **Independent** check of the Cliff–Lorimer arithmetic and relevant EDS operations | Mineral-mapping correctness |
| **PyXRF** | **Secondary** XRF comparator, only where input conversion and experimental assumptions are genuinely comparable | Anything PyMca already covers |
| **XRF-Maps / MAPS** (if practical) | Synchrotron map-level spatial behaviour | Phase identity |
| **Standards** (where available) | Absolute accuracy anchor | Phase identity on unknowns |
| **Expert (domain collaborator)** | **Expert phase-reference** interpretation on the real subset; record the supporting evidence per phase | **Not** "ground truth" unless backed by an independent analytical method; not line-fitting accuracy |

**Pinned comparator versions** (current stable at review; verified to install and
import alongside AXIOMM in one environment): **PyMca 5.9.7** (upgraded from the
2022-era 5.8.0 so the comparison is against the current baseline), **HyperSpy
2.5.0** (core infrastructure), **eXSpy 0.3.2** (the actual EDS/Cliff–Lorimer
implementation used in C3 — `exspy.utils.eds.quantification_cliff_lorimer`; HyperSpy
alone does not evidence that the comparator ran), **PyXRF 1.0.31** (only if added as
a materially-distinct secondary). The standards/reference-material availability
request to domain collaborators is tracked as a **separate** deliverable and does
not block the synthetic and software-differential comparisons.

## 4. Preregistered comparisons

The eight comparisons (C1 net line intensities · C2 overlaps/missing/zero
behaviour · C3 single-energy cation ratios vs an independent Cliff–Lorimer · C4
map-level spatial agreement · C5 abstention & false-positive rates · C6
reproducibility · C7 runtime & memory · C8 provenance completeness) are
**operationalised in `v0.1_acceptance_criteria.md`** — each with exactly what is
measured, the comparator, the error metric and denominator, the zero/near-zero
treatment, the threshold, the justification, and whether a failure is
release-blocking (P0/P1) or diagnostic only.

Decisions from the review are reflected there: **C1** uses synthetic truth as the
primary reference (PyMca differential only), with the margin chosen by a bounded
pilot rule — not a generic 10%; **C3** is a numerical-equivalence check (float64
`rtol=1e-10`, `atol=1e-12`) against a hand-derived oracle plus eXSpy, not a
percentage tolerance; **C4** is Dice-primary / IoU-secondary, gated and diagnostic;
**C5**'s metric is a **false-discovery proportion** (not a false-positive rate),
reported with coverage, abstention and selective risk under a Tier-A/B/C reference
hierarchy. Thresholds are estimated on a **pilot** and **locked before** the
held-out confirmatory run; pilot results are not part of the confirmatory claim.

The line/overlap/ratio cases (C1–C3) and C6–C8 run on **synthetic spectra with
known inputs** first (exact truth); C4/C5 are gated on a Tier-A (independent)
spatial/phase reference (§5). Results are kept on **two separate scorecards** (§6.4):
a task-performance scorecard (where PyMca/PyXRF may legitimately be stronger at
parametric fitting or matrix-aware analysis — reported, not penalised) and a
workflow-assurance scorecard (explicit evidence states, abstention+selective risk,
determinism, save/load fidelity, provenance).

## 5. Datasets

- **Synthetic controlled spectra** — authored with known composition, line set,
  controlled overlaps, and explicit zero-signal cases. These give exact truth for
  comparisons 1–3 and 6. (Build from the existing excitation-aware fusion fixtures.)
- **Tiered reference strategy** (what each reference can and cannot validate):
  - *Synthetic exact truth* — C1–C3 algorithmic validation (exact injected
    components, controlled background/overlap/missing/zero cases).
  - *Thin-film / instrument standards* — detector response, line recovery, energy
    calibration/sensitivity under known conditions; **do not** reproduce a
    geological matrix, so they do not validate mineral-sample matrix effects.
  - *Matrix-matched geological reference materials / characterised mineral mounts*
    — empirical relative/absolute composition error and matrix dependence, measured
    under comparable excitation/geometry/detector/preparation; the available list is
    resolved separately (collaborator request) and their absence does not block
    C1–C3 / C6–C8.
  - *Co-registered EPMA or comparable independent maps* — **Tier A** for C4 spatial
    and C5 phase-level adjudication.
  - Standards may characterise systematic bias but must **not** be used to imply
    matrix-corrected quantitative accuracy AXIOMM does not implement.
- **Real subset** — the five alkaline-mafic samples; the domain expert's
  interpretation is a **Tier-B phase-reference** (not "ground truth"; evidence
  recorded per phase). Use the current pipeline (single-energy baseline; fusion
  labelled experimental), not the stale fused-subset artifacts.
  - **A21-016 evidence status.** A single-energy 13.55 keV XRF spectral map has been
    processed through AXIOMM, and first-pass segmentation, phase-map, spectral-summary,
    composition, reliability and classification outputs exist. These establish real-map
    pipeline execution but are not independent validation references. The current
    validation record does not document a suitable co-registered independent spatial
    phase reference or Tier-A phase adjudication. A21-016 is therefore excluded from
    confirmatory C4 and C5 unless and until the required independent reference evidence
    is documented and shown to be fit for the relevant comparison. Its existing AXIOMM
    outputs may still be used for real-data smoke testing and Tier-B diagnostic review.
    Do not hold the completed ungated comparisons open while awaiting independent
    references. See the A21-016 evidence-status note in `v0.1_acceptance_criteria.md`.

## 6. Procedure (preregistration discipline)

### 6.1 Environment record — commit before the pilot

Record and commit, before any number is produced: the AXIOMM commit; Python
version; PyMca / HyperSpy / eXSpy / (optional) PyXRF versions; NumPy, SciPy,
xraylib, fisx versions; OS and architecture; a complete package lock / environment
spec; baseline configuration files (energy calibration, fit interval, selected
lines/families, background model, peak-shape model, enabled corrections); and the
synthetic-generator commit, data hashes and random seeds.

### 6.2 Sealed pilot → lock → held-out protocol

Before any numerical output, commit: the independent generator specification; the
scenario grid; element and line-family definitions; background and signal strata;
random-seed lists or immutable dataset hashes; the pilot/held-out allocation;
baseline configurations; the metric code or exact mathematical definitions; the
rule for selecting the C1 margin from pilot results; the rule for the number of
held-out Poisson realisations; and the handling of technical execution failures.

- The **pilot** estimates variability and selects among *predeclared* candidate
  tolerances. It must **not** tune a threshold without a predeclared rule, select
  favourable elements/backgrounds, drop difficult cases post hoc, or (if AXIOMM is
  modified) remain part of the confirmatory claim.
- The **held-out** set may contain many predetermined spectra and Poisson
  realisations; it is executed as **one sealed run**. No scientific rerun is
  allowed because a first result is unfavourable. A rerun after a *purely technical*
  execution failure is logged and uses identical bytes, configuration and seeds.
- If the pilot exposes a genuine **P1** defect: record it; reopen the RC under the
  existing rule; make the bounded, **versioned** correction; and generate a **new
  untouched** confirmatory set if the previous one was inspected.

### 6.3 Classifying a result (no post-hoc waiver)

A declared **model-difference** comparison is classified **diagnostic before
execution** and carries **no** blocking equivalence threshold. A preregistered
**blocking** metric that exceeds its threshold **fails** — it is then triaged under
the P0/P1 vs P2/P3 rule (§0); it is **not** retrospectively converted into a pass.
Where possible, comparisons are redesigned so both systems use the same model;
where models cannot be harmonised, the difference is reported descriptively.

### 6.4 Two scorecards (fair comparison)

- **Task-performance** — isolated-component recovery vs truth; overlap/zero
  behaviour; Cliff–Lorimer arithmetic; spatial agreement where referenceable;
  runtime/memory. PyMca/PyXRF may be **stronger** here (parametric fitting,
  matrix-aware analysis) — that is acceptable and must be reported.
- **Workflow-assurance** — explicit evidence states (`measured_positive` /
  `measured_zero` / `not_measured` / `not_excited` / `out_of_coverage`); reliability
  gating; abstention coverage + selective risk; deterministic reruns; save/load
  fidelity; provenance completeness; reproduced effective source selection; and
  visibility of experimental / low-confidence modes in reports.
- Do **not** penalise another package for lacking AXIOMM's full mineral workflow
  (mark the feature out of scope); do **not** infer superior spectral accuracy from
  stronger provenance. AXIOMM's defensible advantage, **if demonstrated**, is the
  *integration* — not being best at every constituent algorithm.

## 7. Stop rule (release gate)

Release v0.1 when **all** applicable conditions hold:

- issue GH #16 remains closed and its bounded tests remain green;
- the frozen existing suite remains green;
- **C2, C3, C6, C8** pass their locked criteria;
- **C1** passes its truth-based criterion after the approved pilot has locked the
  margin;
- **C7** is documented and the declared primary workflow does not fail;
- representative real-data smoke tests complete reproducibly;
- **C4/C5** are either completed against suitable **Tier-A** independent references,
  **or** explicitly declared gated and excluded from stronger phase/spatial accuracy
  claims (the release statement narrowed accordingly);
- all known limitations are visible in user documentation (ties to GH #9);
- installation and the primary public workflow pass in a **clean environment**;
- no unresolved **P0/P1** result remains.

After these conditions are met, **release**. Do not continue auditing merely
because additional improvement is possible.
